# Ferrite Java plugin bridge

The bridge compiles against `io.papermc.paper:paper-api:26.3.build.227-stable`, the newest numbered stable 26.3 build in Paper's Maven metadata when selected. The Gradle toolchain requires Java 25. Run `java/ferrite-api-impl/gradlew.bat build` on Windows (or `./gradlew build` from that directory); the host classpath artifact is `build/libs/ferrite-api-impl-all.jar`. The test plugin has legacy and `folia-supported` variants, plus a dependency fixture.

`PluginHost::start` takes the plugin directory and a `PluginConfig` containing the shaded jar, optional Java home, and an optional typed command back-channel. The JVM is process-wide and cannot be restarted. Call `tick` once per server tick, route tasks returned by `take_region_tasks` to their world/chunk and `take_entity_tasks` to their entity, and call `run_region_task` or `run_entity_task` at the destination. Call `shutdown` after stopping delivery. The server must register live Java player objects before player command dispatch; unresolved senders are denied. `PluginHost::fire_player_join`, `fire_player_quit` and `fire_chat` fire Bukkit's `PlayerJoinEvent`, `PlayerQuitEvent` and Paper's `AsyncChatEvent`/Bukkit's `AsyncPlayerChatEvent`; the JVM reports every registered listener class back through `Native.eventRegistered`, so the host skips the JNI call when nobody listens. A cancelled `AsyncChatEvent` or `AsyncPlayerChatEvent` returns `None` and suppresses the broadcast. `fire_player_move` fires `PlayerMoveEvent` only for movement packets that change position and returns `false` when a listener cancels the move, so the caller teleports the player back. `fire_player_interact`, `fire_block_break`, `fire_block_place` and `fire_player_command` fire Bukkit's `PlayerInteractEvent`, `BlockBreakEvent`, `BlockPlaceEvent` and `PlayerCommandPreprocessEvent` before the server acts; a cancelled block event leaves the world unchanged and resends the original block to the client. Commands declared in a plugin descriptor are registered in Ferrite's dispatcher and run through the plugin's Bukkit `CommandExecutor` with a player or console `CommandSender`; `sendMessage` output made during the call is captured and delivered by the game loop, and the plugin's `TabCompleter` is left to the command map.

Legacy callbacks run under one Java monitor. Folia-supported region and entity callbacks do not take it unless they invoke a legacy listener. Region ownership currently identifies the single chunk supplied with a routed task; multi-chunk ownership is conservatively reported false until the regionizer supplies its full ownership map. Entity ownership is recognized during the routed entity callback. The fallback mode (`-Dferrite.native=false`) drives scheduled work locally in tests.

`Native` exposes logging, one-shot global scheduling, region and entity scheduling, current tick, region-thread checks, and a sender-validated command back-channel. `FerriteServer` implements identity/version/logger, plugin/services managers, online-player registry, console and plugin command dispatch, Bukkit/global/region/async/entity schedulers, and thread/region checks. The remaining generated `Server` methods throw `UnsupportedOperationException` identifying the method; the same applies to unimplemented manager and scheduler operations. This is an initial plugin bridge, not a complete Paper implementation. `tools/Generate.java` is the reflection-based stub generator; run it with the resolved Paper runtime classpath and the interface name to regenerate a stub skeleton.
