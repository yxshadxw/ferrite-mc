OC12 task (hoppers and the missing containers: dispenser/dropper, brewing stand, beacon). Base = current `main` (`50ad5ed`). `git fetch origin` then merge `origin/main`. Read `AGENTS.md`, `docs/handoff/day6-tasks/COMMON-RULES.md`, `game/container.rs`, `game/block_container.rs`, `game/redstone.rs`, `game/furnace.rs` and the menu registry in `ferrite-data`.

Current state: chests, barrels, furnaces, anvils, enchanting, stonecutter, loom, smithing table and grindstone menus exist. Hopper, dropper, dispenser, brewing stand and beacon blocks exist as block states but have no behaviour. Redstone signals are modelled in `game/redstone.rs` with scheduled block ticks.

Implement in commit-sized steps:

1. Hopper (new `game/hopper.rs`): 5-slot inventory, pull one item per 8 game ticks from the container above (furnace/chest/barrel/hopper), push into the container it faces, stop when powered by redstone, and suck up item entities above it. Expose comparator output (fill ratio) and the block entity contents for oc11's persistence (coordinate through a shared block-entity type, do not duplicate storage).
2. Dropper/dispenser: triggered by a redstone rising edge, dropper ejects one item into the facing block/air, dispenser uses its vanilla behaviour for arrows, eggs, snowballs, splash potions and fire charges (projectile spawn via the existing arrow/projectile code); empty or blocked containers do nothing.
3. Brewing stand (new `game/brewing.rs`): 3 bottle slots, ingredient slot, blaze-powder fuel (20 uses), 400-tick brew, bottle fill from water cauldron, vanilla recipes for awkward, mundane, thick, healing, regeneration, strength, swiftness, poison, slowness, harming, invisibility, fire resistance, water breathing, night vision, plus splash via gunpowder and lingering if cheap. Send the brew progress packet/property and the menu title.
4. Beacon (new `game/beacon.rs`): beam height from the pyramid size (1-4 levels of iron/gold/emerald/diamond/netherite blocks), menu with the power buttons, consume one ingot on confirm, apply the chosen effect (speed/haste/resistance/jump boost/strength, regeneration at level 4) to players within the vanilla radius, keep the effect refreshed while in range, and clear it when out of range. Persist the payment/effect via the block entity (oc11 may already be landing; if so, integrate rather than conflict).
5. Tests: a hopper chain moves items chest -> hopper -> hopper -> chest at 8-tick cadence; powered hopper stops; dispenser shoots an arrow; dropper moves an item; brew a speed potion and drink it; beacon grants the effect in range and stops outside; comparator output changes.

Acceptance per commit: `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt --all --check` green (`CARGO_INCREMENTAL=0`, `source tools/env.sh`). Do NOT push or merge into main. Finish with `worker_done` (hashes, test counts, simplifications).
