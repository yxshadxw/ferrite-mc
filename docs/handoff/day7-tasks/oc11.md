OC11 task (entity and block-entity persistence). Base = current `main` (`50ad5ed`). `git fetch origin` then merge `origin/main`. Read `AGENTS.md`, `docs/handoff/day6-tasks/COMMON-RULES.md`, `crates/ferrite-server/src/game/anvil.rs`, `game/playerdata.rs`, `game/entity_index.rs`, `crates/ferrite-entity/src/store.rs` and the chunk NBT writer in `ferrite-world`.

Current state: chunks and player data persist to region files; the entity store (`RegionEntityStore`/`EntityIndex`) is memory-only and mobs/items/arrows vanish on restart. Block entities persist only for chests (verify in `anvil.rs`); furnaces lose contents and burn/cook progress, signs lose text, hoppers/brewing stands/beacons do not persist at all.

Implement vanilla-shaped persistence, one commit per step:

1. Entities per chunk: serialize the region entity store into the chunk's vanilla `Entities` list on save (and read it back on load), or a documented sidecar under the world's `entities/` directory if the chunk writer cannot carry them yet — pick one, document it, and keep UUIDs stable. Cover mobs (health, variant, profession if oc10 landed, position/rotation, AI target optional), item entities (stack, age), arrows, TNT and experience orbs. Do not save players (playerdata already owns them).
2. Chunk lifecycle: load entities when a chunk is loaded, save on unload and on server shutdown, never double-spawn after an unload/reload cycle, and hand off entities correctly when a region transfers a chunk (`Signal::EntityTransfer`).
3. Block entities: persist inventory + progress for furnace/blast furnace/smoker (burn time, cook time, cook total, XP), brewing stand if it exists, hopper/dispenser/dropper contents, beacon (levels, primary/secondary effect, payment), sign text (front/back), and skulls/banners if cheap. Keep chest behaviour and the chunk packet cache invalidation correct.
4. Robustness: corrupt or missing NBT must log and skip that entity/block entity, never panic; unknown entity ids are preserved or dropped with a warning (document which).
5. Tests: save a world to a tempdir with a mob, an item entity, a furnace with items mid-smelt and a sign; reload and assert exact state; unload/reload a chunk twice and assert one entity; restart the server in a test and assert the furnace resumes cooking. Keep `WorldSettings::playerdata = None` in unrelated tests and never share process state.

Acceptance per commit: `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt --all --check` green (`CARGO_INCREMENTAL=0`, `source tools/env.sh`). Do NOT push or merge into main. Finish with `worker_done` (hashes, test counts, what format you chose and what is still not persisted).
