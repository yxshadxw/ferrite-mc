# Ferrite C2 checkpoint

Completed: SNBT numeric forms, arrays, escapes including Unicode names and surrogate pairs, mixed-list wrappers and operations; optional serde conversions; palette width tests and compact; section/chunk heightmaps; packet body and light encoding; Anvil read/write with gzip, zlib, uncompressed, LZ4 Java-block streams, external sidecars and in-process per-file locks; runtime state/biome/block-entity registry and 26.3 chunk NBT conversion.

Validation: expanded real vanilla fixture has 324 full chunks and 517 intermediate chunks in r.0.0.mca; all NBT parses and all full chunks were checked for bedrock, four stored heightmaps, and block-equivalent re-save/reload. Debug measurements from this fixture: mean retained chunk 156,290 bytes including struct and heap, and mean read/decompress/parse/convert 98.338 ms (allocator counter and Instant; excludes registry construction); sample was 324 chunks. Scoped all-feature tests and clippy passed after rustfmt; rustfmt --check also passed.

Remaining / known limitations:
- `crates/ferrite-world/src/registry.rs` `RuntimeRegistry::flags`: motion-blocking comes from generated vanilla block tags, but fluid detection uses a limited aquatic name/property list; wire in the authoritative per-state block properties being developed by F5 and verify all heightmap predicates, including fluid states. Biome IDs are assigned by sorted file names and need alignment with the registry codec order used in the configuration packet.
- `crates/ferrite-nbt/src/snbt.rs` `parse_atom`, `Parser::string` and `Parser::list`: broaden grammar edge cases and malformed-input differential tests against vanilla, particularly underscore placement, string token rules, numeric explicit suffixes, escape edge cases, and empty typed lists; syntax/format behavior is not fully proven. `serde.rs` needs broader Serde type/array/enum interoperability tests and a documented conversion contract.
- `crates/ferrite-world/src/chunk_nbt.rs` `chunk_from_nbt` / `chunk_to_nbt`: test block entities, partial/proto chunks, newly constructed chunk metadata and unknown metadata preservation against vanilla; the fixture currently only performs block-equivalence verification for full chunks. Check storage round-trip for biomes, light, NBT metadata, and entities, and test both directions against vanilla.
- `crates/ferrite-world/src/region.rs` `lz4_read`, `lz4_write`, `RegionFile::write_chunk`: validate LZ4 interoperability with the actual Java implementation, corrupt/malicious headers and decompression limits, external-chunk replacement crash safety and cross-process locking if required. Current locks are shared only within one process.
- `crates/ferrite-world/src/lib.rs` `PalettedContainer::set`: adding or removing a unique value repacks and allocates an entire section, which should be optimized for block-update churn while preserving transition behavior. Validate packet bytes with a vanilla client/protocol implementation and strengthen block-entity and light-mask tests in `network.rs`.
- Fixture lives in gitignored `vanilla/26.3/fixture-world/world/dimensions/minecraft/overworld/region/r.0.0.mca`; the 26.3 server does not use the older world/region location. Intermediate-status chunks legitimately do not contain generated terrain, so the fixture test parses them and checks terrain only on full chunks.
