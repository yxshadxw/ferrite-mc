# Paper-compatible configuration (`ferrite-config`)

`crates/ferrite-config` reads and writes the configuration files an existing Paper/Bukkit
server owner already has, so a server directory can be pointed at Ferrite without a manual
migration step.

## Files

| File | Model |
|---|---|
| `server.properties` | `ServerProperties` — every key generated by vanilla 26.3 |
| `bukkit.yml` | `BukkitConfig` |
| `spigot.yml` | `SpigotConfig` |
| `config/paper-global.yml` | `PaperGlobal` |
| `config/paper-world-defaults.yml` | `WorldSettings` |
| `<world>/paper-world.yml` | per-world overlay on `WorldSettings` |

`FerriteConfig::load(dir)` loads all files (missing files fall back to compiled-in defaults),
`FerriteConfig::save()` writes them back with comments, and
`FerriteConfig::world_settings(name)` resolves a world: values from `<world>/paper-world.yml`
win, everything else falls back to `config/paper-world-defaults.yml`. The per-world path is
`<server dir>/<world name>/paper-world.yml`.

Unknown keys are preserved on rewrite (the raw YAML/properties document is kept alongside the
typed model), and generated files carry a comment above every typed key.

## `server.properties`

Generated from the official 26.3 server (`java -jar server.jar --initSettings` in a scratch
directory, `eula=true`), so key names and defaults are not guesses. All 69 keys are modeled,
including the 26.x additions:

`accepts-transfers`, `chat-spam-threshold-seconds`, `command-spam-threshold-seconds`,
`enable-code-of-conduct`, `management-server-*`, `pause-when-empty-seconds`, `rate-limit`,
`region-file-compression`, `status-heartbeat-interval`, `sync-chunk-writes`,
`text-filtering-*`.

The fixture lives at `crates/ferrite-config/tests/fixtures/server.properties`. To regenerate
it:

```sh
mkdir -p vanilla/26.3/config-scratch
printf 'eula=true\n' > vanilla/26.3/config-scratch/eula.txt
cd vanilla/26.3/config-scratch
JAVA_HOME="C:/Program Files/Eclipse Adoptium/jdk-25.0.5.8-hotspot" \
  "C:/Program Files/Eclipse Adoptium/jdk-25.0.5.8-hotspot/bin/java" \
  -jar ../server.jar --initSettings nogui
```

`management-server-secret` is random per vanilla install; the committed fixture blanks that
one value (so no generated token is checked in), the model's default is the empty string, and
a loaded file's value is preserved. All other defaults match the generated file (the test
compares every fixture key against the typed model).

## UNVERIFIED keys

Keys that were **not** confirmed against the current Paper reference are marked with an
`UNVERIFIED` doc comment in the Rust source and in generated YAML comments. They are kept for
compatibility with older configs.

| File | Key | Why unverified |
|---|---|---|
| `paper-global.yml` | `chunk-system.gen-parallelism` | Present in older Paper; absent from the current reference (`io-threads`/`worker-threads` are current) |
| `paper-global.yml` | `commands.suggest-player-names-when-null-tab-completions` | Present in older Paper; absent from the current reference |
| `paper-global.yml` | `commands.time-command-affects-all-worlds` | Legacy location; current Paper uses `time.affects-all-worlds` |
| `paper-global.yml` | `logging.*` | Section absent from current Paper |
| `paper-global.yml` | `timings.*` | Timings were removed from current Paper |
| all Paper files | `_version_` default | Ferrite's own schema version (1) is written for generated files; existing Paper version numbers are read and preserved |
| `paper-world-defaults.yml` | `spawn.keep-spawn-loaded` | Removed from current Paper |
| `paper-world-defaults.yml` | `spawn.keep-spawn-loaded-range` | Removed from current Paper |
| `bukkit.yml` | `settings.deprecated-verbose` | Three-valued setting, accepted as a boolean or a keyword |
| `bukkit.yml` | `settings.minimum-api` | Newer Bukkit addition |
| `bukkit.yml` | `settings.use-map-color-cache` | Newer Bukkit addition |
| `bukkit.yml` | `aliases` | File name differs between Bukkit versions |
| `spigot.yml` | `settings.log-named-deaths` | Recent Spigot addition |
| `spigot.yml` | `messages.unknown-command` | Default text may have changed |
| `spigot.yml` | `world-settings.default.simulation-distance` | Availability depends on the Spigot version |

Sections that current Paper no longer documents (for example `entities.sounds`) are not typed;
they are still preserved as unknown keys when a file is loaded and saved.

## Semantics and API notes

- **Typed access**: serde structs use `#[serde(default)]` and do not deny unknown fields.
  Missing keys take Paper-compatible defaults.
- **World fallback**: `world_settings(name)` deep-merges the world file over the world
  defaults (mappings recurse, scalars replace). `try_world_settings(name)` reports parse
  errors; `world_settings(name)` falls back to the defaults on error.
- **Comments**: `FerriteConfig::to_yaml_with_comments(file)` and
  `FerriteConfig::world_to_yaml_with_comments(world)` emit Paper-style YAML with a header,
  a comment per known key, and an `UNVERIFIED` marker where applicable.
- **Overrides**: `ConfigOverrides` accepts CLI `--set section.path=value` and environment
  vars. `FERRITE_SERVER_<KEY>` overrides `server.properties`; `FERRITE_CONFIG_OVERRIDES` is a
  semicolon-separated list of `section.path=value` assignments. Sections are `server`,
  `bukkit`, `spigot`, `paper-global`, `paper-world-defaults`, and `world.<name>`. Overrides
  are applied after files load and win over file values; per-world overrides also win over
  `<world>/paper-world.yml`.
- **Version migration**: `ferrite_config::migrate::migrate(kind, &mut value)` runs registered
  steps forward, writes `_version_`, and leaves files with a newer version untouched.
  `PAPER_GLOBAL_MIGRATIONS` currently hoists
  `commands.time-command-affects-all-worlds` to `time.affects-all-worlds`. Add a
  `MigrationStep` and bump `ConfigFileKind::supported_version` to add another.
- **Rewrite safety**: `FerriteConfig::save()` writes unknown keys back unchanged (values and
  nesting; comments on unknown keys are not retained because the raw document is a parsed
  `Value`).
